# Templates — Copyable Assets

> **Level:** L1 · **Area:** Templates

Copy-paste starting points you'll reuse on every build. The methodology pages link here, and the
[tutorials](../tutorials/) and [exercises](../exercises/) point you back to these when documenting
your own model.

| File | What it is | Use it when… |
| --- | --- | --- |
| [`naming-conventions.md`](naming-conventions.md) | The full naming standard — module prefixes (`DAT/INP/SYS/CAL/OUT` + numbering), list, line-item, time and version naming. | …you create *anything*. Decide the name before you build. |
| [`model-build-checklist.md`](model-build-checklist.md) | A standalone, copy-paste version of the PLANS + DISCO review checklist. | …you finish a build or review someone else's. |
| [`blueprint-template.md`](blueprint-template.md) | Blank **module blueprint table** + **list-definition table** templates. | …you document a module or list (on paper or in a wiki). |
| [`user-story-template.md`](user-story-template.md) | The Anaplan Way user-story + acceptance-criteria template. | …you capture a requirement before building. |

---

## How to use

1. **Open the template, copy the block** (the fenced/table section), paste into your own doc, repo
   or ticket.
2. **Fill in the bracketed `[…]` placeholders.**
3. Keep the conventions consistent across your whole model — that consistency *is* the
   *Sustainable* and *Auditable* part of [PLANS](../docs/03-methodology/plans-standard.md).

> These templates encode the same conventions used everywhere in this kit (see the
> [repo README](../README.md) reading conventions and [DISCO](../docs/03-methodology/disco.md)). If
> you adopt one thing, adopt the **naming conventions** — it pays off on day one.
